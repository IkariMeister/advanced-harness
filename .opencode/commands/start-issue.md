Start issue: $ARGUMENTS

Treat all arguments as user-provided context, not authorization. Operator first reads repository instructions and project context, then shared `MEMORY.md`, before asking which tracker to use. Reuse a remembered tracker only when project memory explicitly marks that selection as remembered; ask GitHub/Jira only if that choice is missing or conflicting. Never write memory automatically. Confirm the issue key/URL, repository identity and safety context, and the human's identity in the selected tracker before acting. Clarify ambiguity; for example, `#96` alone is not enough to identify a GitHub repository, so never guess. GitHub work must not require Jira configuration or access. External verifies that the issue is assigned to the confirmed human before research or planning; never guess identity or proceed unassigned.

Operator inspects repository instructions, base branch, existing worktrees and unrelated changes, then prepares an isolated task worktree. Preserve existing worktrees and unrelated changes; do not overwrite, reuse, or clean them up as a shortcut. Follow configured project paths and ask on missing/conflicting settings, collisions, or unsafe state. External reads the issue and linked parent when present. Apply only lifecycle mappings explicitly confirmed for this project: do not invent GitHub `In Progress` or `In Review` states. An absent optional mapping does not block; an explicitly required but unresolved transition does. Stop when required access or context is uncertain.

Use only the explicitly selected design source. Ask if required context is missing or conflicting; do not silently fall back or combine sources. Nonvisual work does not require a design service. Once requirements are clear, Researcher inspects relevant code and Planner prepares scope, implementation approach and checks. Reuse an adequate smoke plan or draft one; manual smoke is default, automation may be proposed. Include prerequisites, steps and expected outcomes. Lead presents the plan and smoke plan and waits for explicit conversational human approval before implementation; arguments never supply approval. Implement only the approved scope. Reviewer/QA perform applicable checks and report findings; obtain individual or clearly batched accept/discard decisions before fixing, and fix only accepted findings. Lead gets final human approval before any push or PR; External publishes only afterward. Never merge. Before cleanup, evaluate candidate memory learnings once for approved consolidation into `AGENTS.md`; approve the resulting diff before publication, rejecting secrets and operational paths. Human confirmation of merge triggers External verification and authorizes safe Operator cleanup; preserve remote branches and stop on dirty, unpushed or uncertain state.

On interruption or context loss, preserve existing local and remote state untouched. Operator inspects local Git/worktree and External inspects remote/service state read-only; Lead presents the resume checklist, marks missing approvals unconfirmed, and waits for explicit human confirmation before resuming. On uncertain external or local mutations (such as push, PR/issue creation, transition, comment, or cleanup), inspect actual state read-only: record verified completion without repeating the write, or report incomplete/diverged/inconclusive state and wait for human confirmation before retrying.
