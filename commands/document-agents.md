Document agents: $ARGUMENTS

Treat arguments as scoping context, not authorization to write files, commit, or publish. This is the on-demand AGENTS.md workflow from ADR-001's Exceptions: it adds no Documentation agent or role on any host, and responsibilities below follow the roles that own them.

Scope selection: Lead confirms the target scope, either the repository root or a specific module path, and the repository identity. Lead may suggest candidate scopes from the repository structure or recent commit/PR activity, but the human selects the scope; never guess one. Lead confirms the mode: greenfield (no `AGENTS.md` exists in the scope yet) or update (revise an existing `AGENTS.md`). In update mode, the human confirms the delta source, such as a commit range, base ref, or explicit list of PRs; ask rather than assume. Missing or conflicting scope, mode, or delta source blocks the workflow.

Operator inspects repository instructions, base branch, existing worktrees and unrelated changes, then prepares an isolated task worktree. Read `worktreeDirectory` and `memoryPath` from project context and ask only on missing, invalid or conflicting settings. Preserve unrelated work.

Analysis: Researcher inspects the scope read-only: build scripts, package scripts, directory structure, architectural patterns, test and verification commands, and every parent and sibling `AGENTS.md` that applies to the scope. In update mode, Researcher also summarizes the confirmed delta (commits, PRs, architectural changes) from the actual history, not from titles alone. Keep the hierarchy consistent: do not duplicate rules a parent `AGENTS.md` already states, and flag conflicts with parent or sibling files instead of silently resolving them. Label every proposed statement as verified (with the file, script, or command output it comes from), inferred, or unknown. Never invent commands, paths, or conventions; flag unknowns for the human.

Proposal: Planner applies the shared `documentation-impact` skill and proposes the outline and the exact diff for each `AGENTS.md` file in scope. Preserve existing human-authored rules and comments; propose a clean minimal diff, never a blind overwrite or full-file replacement of existing content. Lead presents the outline, the exact diff, and the verified/inferred/unknown labels, and waits for explicit conversational human approval of that diff. Arguments, permission prompts, and earlier approvals never supply it. If the human cancels or declines at any point before approval, stop with no disk writes and no Git mutations: no worktree files, commits, branches, pushes, or issues.

Authoring and review: Implementer writes only the approved diff, using the shared `technical-documentation` and `documentation-validation` skills, and records exact check commands and results. A material change from the approved diff returns to the human. Reviewer independently checks the proposed `AGENTS.md` changes against the repository with the shared `documentation-review` skill: re-verify commands, paths, scripts, and claims; the author's explanation alone is not evidence. Lead presents findings; the human accepts or discards each individually or in an explicitly enumerated batch, and only accepted findings are fixed. The shared skills provide procedures only; they make no decisions, grant no permissions, and replace no human approval. Do not copy their procedures into this workflow.

Publication: Before publication, Operator supplies Lead the exact canonical `npm run harness:preflight -- --worktree <path> --base <confirmed-base> --task <key> --json` command, JSON, exit status, worktree, branch, HEAD, and working-change state. Reviewer and QA consume that handoff and do not run the Git-backed wrapper. Missing, malformed, inconsistent, stale, blocked, or inconclusive evidence stops publication; exit 2 takes precedence over exit 1. Exit 0 (including warnings and JSON `approved: true`) is automated evidence only, not human or plan approval. A scoped human exception must identify the current result, worktree, HEAD, working changes, and checks waived; waived checks are never passed. Changes invalidate evidence and exceptions and require a fresh Operator handoff and any necessary renewed approval. Lead separately obtains final human approval before any push or PR. External publishes only afterward, through the standard branch and PR flow. Never merge, force-push, or delete branches.

On interruption or context loss, preserve existing local and remote state untouched. Operator inspects local Git/worktree state and External inspects remote state read-only; Lead presents the resume checklist, marks missing approvals unconfirmed (never inferred from existing diffs or commits), and waits for explicit human confirmation before resuming. On uncertain writes such as push or PR creation, inspect actual state read-only: record verified completion without repeating the write, or report the observed state and wait for human confirmation before retrying.
