# Documentation review

Independently compare documentation with requirements, implementation diff, configuration, and accepted decisions; do not rely solely on the author's explanation. Check material coverage, accurate commands/paths/examples/links, and evidence for claims. Report findings without silently editing the work under review.

Consult the project [glossary](../../docs/glossary.md) and flag undefined project-specific terms or conflicting meanings using required semantic judgment. Distinguish observed facts, unverified behavior, and unsupported capabilities. Skills grant no permissions or decision authority.
