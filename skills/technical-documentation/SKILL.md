# Technical documentation

Update relevant developer guides, configuration references, examples, integration notes, and operational instructions alongside implementation where practical. Verify claims against the code and approved decisions; escalate material deviations rather than rewriting an accepted decision.

Use explicit repository-relative paths in links and path-shaped inline references. Consult the [glossary](../../docs/glossary.md) before using project-specific terms. Explain prerequisites, expected behavior, limitations, and evidence; do not claim checks or runtime behavior that were not observed.
